Lựa chọn · Hướng tiếp cận
Contract-first với OpenAPI 3.1
openapi/openapi.yaml
Nhóm chọn contract-first vì
  • Đề yêu cầu validation và tài liệu dùng chung một nguồn schema
  • Một file spec cho validator, Swagger UI và test đối chiếu response
  • Spec là hợp đồng, người khác đọc được mà không cần đọc code
Không chọn
Code-first (zod + zod-to-openapi)
Spec bị sinh ra từ code, nhóm không thiết kế hợp đồng trước khi code
Tài liệu viết tay (README, Google Docs)
Lỗi thời ngay khi code đổi mà không ai biết
Hai schema riêng (YAML và trong code)
Hai bản sẽ lệch nhau, đúng lỗi thường gặp mà đề cảnh báo
Lựa chọn · Nền tảng
Express + TypeScript
express 5 · typescript
Nhóm chọn Express vì
  • Framework quen thuộc, tài liệu và ví dụ nhiều
  • OpenAPI validator, Swagger UI và pino đều có middleware cho Express
  • TypeScript bắt lỗi kiểu ngay khi viết code
Không chọn
NestJS
Nhiều khái niệm (module, decorator) hơn mức cần cho 7 endpoint
Fastify
Bộ OpenAPI validator và Swagger UI nhóm dùng viết cho Express
Spring Boot (Java)
Khác ngôn ngữ, cần thêm JDK và công cụ build; nhóm thống nhất dùng TypeScript
Lựa chọn · Database
SQLite, SQL thuần
better-sqlite3
Nhóm chọn SQLite vì
  • Máy sạch chỉ cần Node, không cần Docker hay cài DB server
  • Giữ đúng tên bảng, cột, constraint của đề
  • SQL thuần và transaction đủ cho 3 bảng
Không chọn
Docker + PostgreSQL
Phải cài Docker và chạy DB server, khó chạy lại trên máy sạch
Prisma, Drizzle (ORM)
Thêm lớp trừu tượng, trong khi SQL thuần đã đủ cho 3 bảng
Đánh đổi: uuid thành TEXT, boolean thành INTEGER, chưa kiểm tra trên PostgreSQL thật.
Lựa chọn · Validation
OpenAPI validator
express-openapi-validator
Nhóm chọn vì
  • Đọc thẳng openapi.yaml nên validation và spec dùng chung một nguồn
  • Chặn request sai (400) trước handler, không chạm DB
  • Test bật kiểm tra response để phát hiện code lệch spec
Không chọn
zod
Schema nằm trong code, thành hai nguồn nếu vẫn giữ openapi.yaml viết tay
Joi, class-validator
Cũng là schema trong code, không đọc được từ spec
Ajv tự viết middleware
Phải tự viết phần đọc spec và kiểm tra response, thư viện đã làm sẵn
Lựa chọn · Documentation
Swagger UI
swagger-ui-express · /docs
Nhóm chọn Swagger UI vì
  • Phổ biến, nhiều tài liệu hướng dẫn
  • Có Try it out để gửi request ngay, nút Authorize để dán Bearer token
  • Đọc từ chính openapi.yaml nên tài liệu không bị lệch
Không chọn
Redoc
Tập trung vào đọc tài liệu, bản miễn phí không có Try it out
Scalar
Dùng được, nhưng mới hơn và ít tài liệu hướng dẫn hơn Swagger
Postman
Phải import spec riêng, không đi kèm server tại /docs
Lựa chọn · Authentication
JWT Bearer token
jsonwebtoken · HS256 · POST /login
Nhóm chọn JWT vì
  • Cần token để dùng Bearer Authentication cho các endpoint cart
  • Stateless: server chỉ kiểm tra chữ ký và hạn, không lưu token
  • User cố định nên không cần bảng users hay API register
Không chọn
Session và cookie
Phải lưu session ở server, và không phải Bearer token
Basic Auth
Gửi username và password trong mọi request
API key tĩnh
Không có hạn dùng và không gắn với bước đăng nhập
Đánh đổi: chưa có logout, không thu hồi được từng token.
Lựa chọn · Logging
pino + file app.log
pino · pino-http · npm run logs
Nhóm chọn pino vì
  • Ghi log JSON mặc định, có sẵn pino-http cho Express
  • Mỗi request có request_id (header, error body, dòng log)
  • Ghi ra logs/app.log, lệnh npm run logs lọc theo request_id, status, level
Không chọn
ELK Stack, Grafana Loki
Phải dựng thêm server (thường bằng Docker), quá nặng cho app nhỏ
winston
Cấu hình nhiều hơn, pino đã đủ cho nhu cầu của nhóm
morgan
Chỉ ghi access log, không có log có cấu trúc cho lỗi
Đánh đổi: không có dashboard, cảnh báo; file log chưa tự xoay theo ngày.
